**Question:** Why does a skill instruction allowing file edits fail to establish that an agent can edit a particular file?

- A. The instruction changes model weights before the file operation is attempted.
- B. The file becomes editable when its path is mentioned in the instructions.
- C. The instruction transfers the skill author's file access to the current agent.
- D. The operating environment must supply the necessary tool and permission.

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. Loading a skill supplies guidance rather than retraining weights. Whether an operation can run depends on the tools and permissions in the environment.
- B. Not quite. A path identifies a possible target; mentioning it does not grant access. The operating environment must supply a permitted way to edit that target.
- C. Not quite. Sharing a procedure does not transfer the author's permissions. Access must be available in the environment carrying out this run.
- D. Correct. A skill describes intended behavior, but instructions do not grant access or create a secure sandbox. The harness operates under the current environment's execution constraints.
