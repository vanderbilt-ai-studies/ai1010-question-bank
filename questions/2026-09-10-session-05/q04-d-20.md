**Question:** Why does turning a one-time skill into a persistent process require additional failure testing?

- A. Repeated execution repairs errors by retrying the unchanged procedure
- B. Saved progress eliminates the need to check whether required inputs are present
- C. An available execution host establishes that every requested action is appropriate
- D. An unattended process can repeat the same error across runs

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. Repetition can reproduce the same error, so define failure behavior and test it before relying on unattended runs.
- B. Not quite. Saved state supports continuity, but later runs can still encounter missing inputs or access.
- C. Not quite. Host availability enables operations; allowed actions and verification criteria still need to be defined.
- D. Correct. Persistent operation adds opportunities for recurring mistakes. Test failure cases and define when the process should stop.

</details>
