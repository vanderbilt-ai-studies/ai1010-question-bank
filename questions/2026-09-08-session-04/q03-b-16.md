**Question:** A colleague claims a new frontier model must be more capable purely because its embedding space and MLP (multi-layer perceptron) matrices got wider. Based on the lecture, what alternative explanation should you also consider?

- A. The model might also have more decoder stacks, making the pipeline deeper rather than wider
- B. The model might simply have a longer maximum context window, letting it hold more of the prompt at once
- C. The model might use a smaller embedding space, which forces it to represent meaning more efficiently
- D. The model might be running on faster hardware, so the same computation simply finishes sooner

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. Session 3 gave you width -- wider MLP (multi-layer perceptron) matrices and a bigger embedding space. Today's session adds length: the same attention-then-MLP block repeated more times. A bigger model can grow either way, so width is not the only explanation on the table.
- B. Not quite. A longer window changes how much you can put in front of the model, not how much computation the model does with it. The lecture keeps window size separate from the levers that make a model tier bigger.
- C. Not quite. This runs the lever backwards. A larger embedding space is one of the width increases that comes with a bigger model tier, so shrinking it is not what a step up in capability looks like.
- D. Not quite. Faster hardware gets you the same answer sooner, not a better one. Everything the lecture offers as a real difference between model tiers is about the shape of the pipeline, not the speed it runs at.
