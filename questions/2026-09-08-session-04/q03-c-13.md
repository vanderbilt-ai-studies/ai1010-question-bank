**Question:** Beyond memory and task tracking, what 'less obvious' capability did the lecture say a harness gives an agent?

- A. Command-line tools such as bash, run across many files
- B. A much bigger context window that holds more of the conversation
- C. Direct access to the model's training data for looking facts up
- D. Faster token generation, so that long tasks finish sooner

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. The lecture singles this out: a harness lets an agent compose filtering and extraction steps across many files, and it argues models have become unusually good at writing those commands. A chat session has no files to point them at.
- B. Not quite. That is a property of the model and its limits, not something the surrounding harness supplies. The capability highlighted was reaching outside the conversation, to files and tools.
- C. Not quite. A model does not consult its training data as a searchable store, and a harness does not give it one. What the harness adds is access to files and tools outside the model.
- D. Not quite. Speed is not what a harness changes. The point was that an agent can reach for command-line tools and a file system, which a chat session cannot use at all.
