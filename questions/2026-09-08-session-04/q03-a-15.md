**Question:** Why does seat-minder look up student names and photos from a roster at runtime instead of hard-coding them into the program?

- A. Hard-coding names and photos would make the app run noticeably slower
- B. Runtime lookups of this kind are required by the Vercel hosting platform
- C. It keeps personal data out of the code itself, by design
- D. It lets the app work for a student not yet added to the roster

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: C**

- A. Not quite. Speed is not the reason given. The reasoning is about privacy, and about a habit worth keeping whenever an agent handles personal data.
- B. Not quite. No hosting requirement of this kind is mentioned; the practice is described as a general good habit, not a constraint of the platform.
- C. Correct. The program knows only that a roster and a set of images exist somewhere it can read, which is the same privacy-by-design pattern this course's own FERPA-safe roster tooling uses.
- D. Not quite. Missing roster entries are not discussed. The stated reason is keeping personal data out of the program rather than covering an edge case.

</details>
