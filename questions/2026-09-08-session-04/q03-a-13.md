**Question:** What lesson does the seat-minder build illustrate about directing an agent to write software, according to the notes?

- A. Moving the typing to an agent does not remove the need to state requirements
- B. An agent finds and fixes every bug in a build without being asked to
- C. Agents can only build software that has no database behind it at all
- D. Directing an agent removes the need for a clear problem statement first

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. Correctness, concurrency, and privacy still have to be asked for out loud. The seat-minder concurrency risk is the same category of bug a hand-written system would have to guard against.
- B. Not quite. The notes show the opposite: defensive, non-blocking code had to be requested explicitly rather than turning up unprompted.
- C. Not quite. Seat-minder runs on a Postgres-compatible database, so the notes contradict this one directly.
- D. Not quite. The sequence runs the other way: the North Star problem statement came first, and the agent-directed build followed from it.
