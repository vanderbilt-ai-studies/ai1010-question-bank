**Question:** What fix does the lecture propose for grading many student submissions consistently, and why does it solve the context-bleeding problem from grading in one long chat?

- A. Use one long chat, but tell the model to ignore everything it graded earlier
- B. Reduce the sampling randomness so grades come out the same regardless of order
- C. Give an agent the submissions, the rubric, and a grading skill, one subagent each
- D. Have a human grade the first several submissions to warm the model up first

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: C**

- A. Not quite. Asking the model to ignore earlier content does not remove that content from what it is attending to. The fix described actually separates the submissions instead.
- B. Not quite. Lowering randomness does nothing about information carrying forward from one submission to the next. The bias comes from earlier context, not from chance variation.
- C. Correct. Each submission gets its own fresh subagent, so no earlier grading is sitting in that subagent's context. Every submission is judged against the same fixed standard, with nothing carried over.
- D. Not quite. This is not part of the fix described, and it would make things worse rather than better -- more prior grading in context is exactly the source of the bias.
