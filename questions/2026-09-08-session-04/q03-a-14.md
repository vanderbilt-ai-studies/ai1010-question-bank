**Question:** What does it mean that seat-minder was built as a 'clean room' with respect to student data?

- A. The app was tested in a sandboxed environment with no live student data
- B. Only the instructor was allowed to view the completed app
- C. The database was wiped at the end of each semester
- D. The code itself never has any student's name or photo written into it directly

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. That is a reasonable everyday reading of 'clean room', but here the term is about the code itself rather than about a separate testing environment.
- B. Not quite. The teaching view is used in class, but who is allowed to look at the app is not what 'clean room' refers to here.
- C. Not quite. Data retention is not discussed in the notes. The clean-room point is about what the code does and does not contain.
- D. Correct. The program is written to know that a roster and a set of images exist somewhere it can read, and to look them up at runtime, rather than carrying anyone's name or photo inside it.
