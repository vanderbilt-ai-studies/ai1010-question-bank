**Question:** Why are skills portable across different model providers, according to the lecture?

- A. Because every provider agreed to a shared API (application programming interface) standard for skills
- B. Because a skill is compiled into a single universal binary before it runs
- C. Because a skill is just files and instructions, not code tied to one vendor, so any harness that understands the same format can run it
- D. Because skills never contain any structure, only plain paragraphs of English

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: C**

- A. Not quite. No shared industry API was described -- portability comes from what a skill is made of, not from a formal cross-vendor agreement.
- B. Not quite. Compiling to a binary would tie a skill to one execution environment, which is the opposite of the plain-files approach the lecture described.
- C. Correct. Because a skill is just files and instructions rather than vendor-specific code, any agent whose harness understands the same skill format can run it -- which is exactly why a skill could move between model providers.
- D. Not quite. Skills do have structure -- a name, description, instructions, and often scripts and reference files -- the portability comes from that structure being format-based, not vendor-based, not from having no structure at all.
