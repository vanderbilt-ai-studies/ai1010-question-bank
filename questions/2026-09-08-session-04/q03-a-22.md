**Question:** The lecture stresses that a reasoning model generates tokens one at a time in exactly the same way a non-reasoning model does. Where, then, does its ability to check itself before answering come from?

- A. From post-training, very likely a form of reinforcement learning
- B. From a separate verification model that checks each draft answer
- C. From a wider embedding space in the larger model tiers
- D. From pre-training on a corpus made up mostly of step-by-step explanations

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. Nothing about token-by-token generation changes. What post-training adds is the habit of spending some of those tokens on a private scratch space -- restating the problem, trying answers, weighing them against each other -- before committing to a reply.
- B. Not quite. It is tempting to picture a second model marking the first one's work, but the lecture describes one model producing one stream of tokens. The checking happens inside that stream, not in a reviewer standing beside it.
- C. Not quite. Width is one of the levers that makes a model tier bigger, but the lecture keeps raw size separate from whether a model reasons. Reasoning is a behaviour training installs, not a size a model grows into.
- D. Not quite. Pre-training is where a model picks up what it knows about the world. The lecture puts this capability one stage later, in the training that shapes how a model uses what it already knows.
