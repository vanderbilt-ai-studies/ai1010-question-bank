**Question:** Why would a model meant to operate as an agent for long, multi-step tasks make a different trade-off about reasoning than a model built purely for fast chat replies?

- A. Because an agent has to reason before it can generate any text at all.
- B. Because reasoning tokens do not count against an agent's context window budget.
- C. Because the harness does the reasoning for the agent, on the model's behalf.
- D. Because long tasks benefit from reasoning at each step, while chat trades it for speed.

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. Agents generate tokens the same way any model does. Reasoning is a mode available to them, not a precondition for producing text at all.
- B. Not quite. Reasoning tokens occupy context like any other tokens, for agents and chat alike. The lecture's distinction was about intended use -- long multi-step work versus instant replies -- not about how tokens are counted.
- C. Not quite. The harness supplies a file system, memory, task tracking, and skills; it does not think for the model. Reasoning still happens inside the model, which is why keeping it available matters for long agent work.
- D. Correct. An agent working through many linked steps benefits from having reasoning available throughout, whereas a product optimized for quick back-and-forth makes the opposite trade-off.

</details>
