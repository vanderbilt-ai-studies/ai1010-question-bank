**Question:** An agent works through a long, multi-step coding task without losing track of earlier decisions, even though its visible reasoning trace does not show every internal adjustment it made. Which architectural idea from the lecture best explains this kind of stability?

- A. Looping -- re-running a representation through the same stack so it settles first
- B. A larger context window, so nothing from earlier in the task ever falls out of view
- C. More decoder stacks, so the pipeline runs longer before producing each token
- D. Wider MLP (multi-layer perceptron) matrices alone, with no change in passes

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. One pass through a stack can leave a representation a little unstable. Sending it back through the same stack lets it settle into a more solid state before it moves on, which is what the lecture ties to holding a long task together -- and because that extra pass produces no new token, it never shows up in the visible trace.
- B. Not quite. This is a real and tempting answer, since a long task does need earlier decisions to stay available. But a bigger window is the chat-shaped fix; the lecture's answer for holding a long task together is an agent writing things down outside itself, and the stability described here is a property of the representation, not of how much text is in view.
- C. Not quite. Depth and looping are two separate levers in the lecture, and it is easy to run them together. More stacks means more different blocks in sequence; looping means the same block run again on its own output, which is the one connected to settling into a stable state.
- D. Not quite. Width is the Session 3 lever, and the lecture keeps it distinct from what today added. Making each block wider does not give a representation a second pass to settle in.
