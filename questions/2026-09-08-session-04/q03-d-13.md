**Question:** What specific problem was described with two similarly named skills, and how was it fixed?

- A. Two very similarly named skills served the same purpose, with no reliable way to know which one the model would pick; the fix was to remove the duplicate
- B. Two skills used incompatible file formats, so one was rewritten from scratch in a different format
- C. Two skills both tried to write to the same output file, causing a crash, so the output files were renamed
- D. Two skills produced identical output every time, so their instructions were combined into a single longer file

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. This matches what was described: an "AI class lecture recording to lecture notes" skill and "lecture recording to lecture notes" were similar enough that the model could not reliably tell them apart, so the duplicate was simply deleted.
- B. Not quite. No format incompatibility was described -- the problem was about the model choosing between two similarly named skills, not about the skills being unable to run at all.
- C. Not quite. A file-write crash is a different kind of bug than the one described. The actual issue was ambiguous selection between two skills with near-identical names and purposes, not a technical collision while running.
- D. Not quite. The problem was not that the two skills produced the same output -- it was that their names were similar enough that the model had no reliable way to choose between them for a given request.
