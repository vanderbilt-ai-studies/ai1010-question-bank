**Question:** Why does the lecture call computer use 'genuinely difficult,' rather than a solved problem?

- A. Because screenshots take up too much storage space to be practical
- B. Because most software is not built to be operated with a mouse and keyboard
- C. Because the model must translate between two programming languages at each step
- D. Because even the best systems today finish only some of the tasks people find easy

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. Storage is not the issue raised. The difficulty described is about completing tasks correctly, not about how much space images occupy.
- B. Not quite. Everyday software is built exactly for mouse-and-keyboard use by people, which is why an agent has to learn to click and type the way a person does. That is not the source of the difficulty.
- C. Not quite. No language translation is involved. The work is interpreting an image and choosing where to click or type, which is a different kind of problem entirely.
- D. Correct. Realistic desktop benchmarks are the evidence the lecture leans on: current systems fall well short of what a person does without thinking about it, which is what keeps this an open problem rather than a finished one.
