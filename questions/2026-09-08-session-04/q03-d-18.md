**Question:** A student asked whether writing several detailed paragraphs of instruction into a skill risks the same context problems as an overloaded chat conversation. What was the answer?

- A. Yes, so skill instructions should always be kept to one paragraph or less
- B. No, because a skill's instructions sit right next to the work they govern
- C. Yes, but only for skills that also include scripts or other runnable code
- D. No, because skill instructions are processed by a completely separate model from chat

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: B**

- A. Not quite. No length limit was set. The answer turned on where instructions sit relative to the task, not on capping how many paragraphs they run to.
- B. Correct. The instructions arrive attached to the specific task at hand rather than competing for attention against a long, wandering chat history, which is what makes an overloaded conversation lose the thread in the first place.
- C. Not quite. The answer carved out no exception for code-bearing skills. Instructions sitting next to the relevant task holds whether or not the skill bundles scripts.
- D. Not quite. Nothing suggests a second model handles skill instructions. The same model reads them -- just without the competing clutter of a long conversation around them.
