**Question:** Why does the lecture treat a skill's name and description as unusually important to get right?

- A. Because those two fields are the only ones a course platform shows to students
- B. Because that short text is all the model has to judge whether a request matches
- C. Because a longer name and description take the harness longer to parse each turn
- D. Because the name and description are the only parts of a skill you can share

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: B**

- A. Not quite. This is not a course-platform question. The name and description matter because of how the agent decides whether a skill applies, not because of what a student interface happens to display.
- B. Correct. Only the name and description are resident before a skill loads, so that short text is the model's entire basis for matching a request to a skill. A vague or duplicated name therefore gets the wrong skill triggered, or none at all.
- C. Not quite. Parsing time was not the concern raised. The worry was about matching the right request to the right skill, not about how fast the text is processed.
- D. Not quite. Sharing a skill means passing along the whole set of files. What is special about those two fields is their role in triggering, not any limit on what can be handed to someone else.
