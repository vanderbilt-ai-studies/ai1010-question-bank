**Question:** Suppose you are directing an agent to build a new app that will display students' photos next to their quiz scores. Based on the privacy-by-design pattern described for seat-minder, what should you ask the agent to do?

- A. Embed a snapshot of the current roster and photos directly into the app's code so it always has the data on hand
- B. Have the app read student names, photos, and scores from a roster and gradebook source at runtime, the way seat-minder reads its roster and images
- C. Store the data in a spreadsheet emailed to every student
- D. Ask the agent not to worry about privacy since it is only used by the instructor

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: B**

- A. Not quite. This is exactly the hard-coding pattern seat-minder was built to avoid. The notes favor looking data up from a source rather than writing it into the program.
- B. Correct. This mirrors the pattern the notes describe: the code should know a data source exists and look it up, rather than having personal data written into the program itself.
- C. Not quite. Broadly distributing personal data to every student is not the privacy pattern described. The notes emphasize the program looking up data it needs, not sharing it out.
- D. Not quite. The notes present privacy-by-design as a general habit to build in regardless of who else can see the interface, not something to skip because access seems limited.
