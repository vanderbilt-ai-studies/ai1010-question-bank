**Question:** Which part of a skill stays loaded in an agent's context even when the skill is not currently being used?

- A. Its name and description
- B. The full body of its instructions
- C. Any scripts it bundles, such as a frame-extraction script
- D. Its reference files and output-format examples

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. The name and description are what let the model recognize a matching request before anything else about the skill has loaded, so those two pieces stay resident even when the skill is idle.
- B. Not quite. The instruction body is exactly the part that loads only on demand, once the skill is actually triggered by a matching request. Keeping it resident all the time is what the on-demand design avoids.
- C. Not quite. Scripts are among the heaviest parts of a skill, which is why they load only when the skill actually runs, not just because the skill exists in the library.
- D. Not quite. Reference files and output-format examples are useful once the skill is in use, but loading them permanently for every skill in a library would recreate the exact bloat the on-demand pattern is built to prevent.

</details>
