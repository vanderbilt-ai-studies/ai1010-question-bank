**Question:** A classmate is deciding whether to use a reasoning-enabled model or a non-reasoning model for a task that involves several small, easy-to-miss details, similar to the day-of-week calculation from Lab 1. Based on the debrief, what should they expect?

- A. The reasoning model is more likely to succeed, since it can check answers first
- B. There should be no difference, since both generate tokens the same basic way
- C. The non-reasoning model is more likely to succeed, because it avoids overthinking
- D. Neither model can be trusted with a task that turns on small details

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: A**

- A. Correct. That is the Lab 1 finding: the non-reasoning model committed immediately and got it wrong, while the reasoning model could compare candidates before settling on one.
- B. Not quite. Both do generate tokens the same basic way, which makes this tempting, but the extra step of checking work before committing is exactly what separated the two results.
- C. Not quite. Speed is not accuracy here. On this task the faster model was the one that got the answer wrong, having committed with no chance to look again.
- D. Not quite. The reasoning-enabled model handled this exact kind of fiddly-detail task, so the honest conclusion is about which mode you pick, not about giving up on both.
