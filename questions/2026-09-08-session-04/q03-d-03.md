**Question:** You have dozens of skills installed, yet a conversation that uses none of them is no more crowded than before. What explains that, per the lecture?

- A. Each skill is compressed into a much shorter summary before it is stored
- B. The harness unloads and deletes any skill that has not been used for a while
- C. Only a skill's name and description stay in context; the rest loads when it triggers
- D. Every skill is capped at the same fixed token length no matter what it does

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: C**

- A. Not quite. Compression is not the mechanism. The instruction body is not shrunk at all -- it is simply left out of context until a request needs it.
- B. Not quite. Deleting unused skills was not part of the explanation given, and it would mean losing a skill rather than simply not paying its context cost yet.
- C. Correct. An idle skill costs almost nothing, because only its short name and description are resident. The body, the scripts, and the reference files enter context only once a request actually matches it.
- D. Not quite. A cap would not distinguish an idle skill from an active one. The point was about when a skill's content loads, not how long any one skill is allowed to be.
