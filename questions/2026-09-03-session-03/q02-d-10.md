**Question:** A classmate installs a model on a laptop with no GPU (graphics processing unit) and says the answer crawls out a word at a time, while the same kind of model in a browser feels close to instant. What best explains the gap?

- A. The local copy has fewer parameters, so it needs more time to reach the same answer.
- B. The hosted copy runs on hardware that produces roughly ten times more tokens per second.
- C. The browser holds the whole answer back until it is finished, so nothing is genuinely faster.
- D. The laptop has to re-encode the entire context before each token, which the server avoids.

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: B**

- A. Not quite. Fewer parameters means less capability, not more time -- a smaller model is the faster one, all else equal. The gap here is hardware, not model size.
- B. Correct. About 5 tokens per second on a bare laptop against roughly 60 from a hosted service is more than an order of magnitude, and you feel every bit of it because generation is sequential. Same architecture, same code -- different hardware doing the arithmetic.
- C. Not quite. Hosted interfaces stream tokens as they arrive, which is why you watch text appear. The speed difference you are seeing is real, not a display trick.
- D. Not quite. Neither one starts over per token -- that is what stored state such as the KV (key/value) cache is for, and it is part of the same software in both places. The laptop is simply doing the arithmetic on slower hardware.
