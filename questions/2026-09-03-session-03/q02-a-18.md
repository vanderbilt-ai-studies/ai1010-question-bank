**Question:** Asked which of two model tiers is faster and which is less capable, the class named the smaller one both times. Why is the same answer right twice?

- A. Because the smaller tier skips stages of the pipeline that the larger one runs.
- B. Because the smaller tier is given a shorter thinking budget by default.
- C. Because vendors deliberately slow the larger tier to encourage upgrades.
- D. Because both follow from size -- fewer numbers to run and to hold.

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. Both tiers run the same pipeline end to end; a tier is that architecture built bigger, not a stripped-down version of it. What differs is how big each piece is.
- B. Not quite. The thinking budget is a separate dial you set yourself, and it is not what makes a small model quick. Size alone explains both the speed and the ceiling.
- C. Not quite. No throttling is needed. A bigger model genuinely has more numbers to push every token through, so it is really slower and really more capable.
- D. Correct. A tier is the same architecture built bigger, so speed and capability move together in opposite directions. One is paid for with the other.
