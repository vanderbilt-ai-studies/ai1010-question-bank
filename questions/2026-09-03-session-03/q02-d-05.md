**Question:** When you first submit a large context to a model, how is that context handled?

- A. Strictly one token at a time, in the order you typed it
- B. In chunks, with each chunk finished before the next one starts
- C. Token by token, but faster than generation because nothing is written to the screen
- D. Largely in parallel, since it arrives all at once

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. That describes generation, not intake. Your context is already complete when it arrives, so there is nothing to wait for and the model does not have to walk it in sequence.
- B. Not quite. Staging it that way would still make one part of your context wait on another, and that waiting is what makes generation slow. Because the whole context is present from the start, much of the work over it can go on at the same time.
- C. Not quite. Display is not the bottleneck. Generation is slow because each token depends on the one before it -- and that dependency simply does not exist for text you have already supplied.
- D. Correct. The whole context is available up front, so the work over it can be spread out rather than serialized. That is why pasting a long document costs surprisingly little time compared with waiting for a long answer.
