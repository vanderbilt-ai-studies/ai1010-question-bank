**Question:** As a model produces the tenth token of its answer, what happens to the context it has already processed?

- A. Every earlier token is encoded and embedded again from scratch, once per new token.
- B. The earlier context is thrown away, and the model works only from the token it just wrote.
- C. Only a short summary of the earlier context is kept, and the individual tokens are dropped.
- D. Stored state is reused -- the KV (key/value) cache -- so the same work is not repeated.

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. That would make generation vastly slower than it is, and slower still as the answer grew. The model does reinterpret the context, but it does not start the whole job over.
- B. Not quite. If that were so, the model could not stay on topic past a sentence. The earlier context is still very much in play -- what changes is that the model avoids redoing work it has already done on it.
- C. Not quite. Nothing is compressed away like that; the whole context is still there for the model to work over. What gets saved between tokens is repeated computation, not the text itself.
- D. Correct. There are well-known tricks for keeping state around so earlier work is not thrown away, and the KV cache is the one people name. When a vendor says their model is special because of its KV cache, this is what they are talking about.
