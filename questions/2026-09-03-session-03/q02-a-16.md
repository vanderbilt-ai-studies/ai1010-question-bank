**Question:** On an everyday task you cannot tell a small tier's answer from a large tier's. What does the lecture say that means?

- A. The picker most likely routed both requests to the same model.
- B. The task was too poorly specified for either model to do it well.
- C. The task did not need the extra capability the larger tier has.
- D. The difference is there but shows only in wording, not in substance.

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: C**

- A. Not quite. The picker sends your request to the tier you chose. Matching answers mean the task was easy enough for both, not that one was quietly substituted.
- B. Not quite. A vague prompt usually produces two different bad answers rather than two equally good ones. Matching answers point to a task that sat within reach of both.
- C. Correct. Differences between tiers only surface when a problem is hard enough to expose them. If the small one already got it right, the extra capability had nothing to do and paying for it buys you nothing.
- D. Not quite. Wording varies from run to run even within a single tier, so it is not the tell. On an easy task there is no substantive gap to find in the first place.
