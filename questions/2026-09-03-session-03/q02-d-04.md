**Question:** Why does a model take noticeably longer to write out a long answer than to take in a long prompt?

- A. The prompt is usually shorter than the answer, so there is simply less of it to process.
- B. Taking in the prompt skips the decoder stacks, which only run during generation.
- C. Most of the prompt is handled at once, while each token waits on the one before it.
- D. Generation runs slower because the model raises its accuracy while it is answering.

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: C**

- A. Not quite. Length is not the explanation -- paste in a very long document and it is still absorbed quickly. The difference is in how the two phases run, not in how many tokens each one involves.
- B. Not quite. The decoder stacks run over the prompt too; that is how the model builds any representation of it at all. What differs is that the prompt's tokens do not have to wait for each other.
- C. Correct. The context arrives as one big collection and is processed largely in parallel. Generation cannot work that way -- each token has to be produced and fed back in before the next can be chosen, and that sequential loop is the slow part.
- D. Not quite. There is no separate accuracy setting that kicks in mid-answer. The slowdown is structural: generation is a one-at-a-time loop, whereas reading the context is not.
