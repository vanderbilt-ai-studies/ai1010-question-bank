**Question:** A model produces a paragraph with a clear beginning, middle, and end. Given that it only ever chooses one token per run, where does that structure come from?

- A. The model wrote an outline first and then filled each section in
- B. The model produced the ending first and then worked backwards to reach it
- C. The app split the request into sections and asked the model for each one
- D. It emerges as the paragraph is written, since each token is chosen from everything written so far

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: D**

- A. Not quite. Planning ahead is how you would write a paragraph, so it is the natural guess. There is no outline stage in the pipeline: every run produces exactly one token, and nothing is kept between runs except the context itself.
- B. Not quite. Generation only ever moves forward. Once a token is chosen it becomes part of the context and the next one is chosen from there, so there is no ending sitting in place to write toward.
- C. Not quite. Nothing splits the request up. One run yields one token, and the paragraph is that single loop repeated, not several separate answers stitched together.
- D. Correct. Every run reads the whole context, including the part of the answer already produced, so a sentence that has opened a topic makes the tokens that close it more likely. Shape comes out of the loop rather than out of a plan.
