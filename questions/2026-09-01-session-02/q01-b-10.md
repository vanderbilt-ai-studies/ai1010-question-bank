**Question:** A student watches a chat model pause for a second and then produce its answer a word or two at a time. She concludes her internet connection is slow. What is the better explanation?

- A. The full answer was finished before anything appeared and is shown gradually to feel conversational
- B. Each piece of text is the model completing a full run and producing one more token
- C. The server is holding her request in a queue behind other users
- D. Her browser is rendering the text more slowly than it received it

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: B**

- A. Not quite. There is no finished answer waiting. Each fragment appears only when a fresh run of the model has produced it, so the trickle reflects real work happening.
- B. Correct. The pause and the trickle are the model itself running, once per token. Every visible fragment means the whole pipeline just executed again on a slightly longer context.
- C. Not quite. Queuing can add delay before the first word, but it does not explain the steady word-by-word arrival afterward. That rhythm is the model generating one token per run.
- D. Not quite. Browsers render text far faster than it arrives here. The pacing is set upstream, by how long each run of the model takes to produce the next token.
