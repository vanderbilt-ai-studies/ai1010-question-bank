**Question:** A student asks a chatbot the same question in two fresh chats and gets different answers. They conclude that the model must be broken, or else remembering them from the first chat. What is actually going on?

- A. The model is comparing the two chats and deliberately varying its wording
- B. Noise at each token choice sends the model down a different path each time
- C. The model's parameters shifted slightly as it learned from the first chat
- D. A glitch in the decoder stacks produced slightly different probabilities

<details>
<summary>Show the answer and why each option is right or wrong</summary>

**Answer: B**

- A. Not quite. Fresh chats share nothing; the second run sees only its own context. The variation is not a deliberate comparison but the ordinary effect of noise at each token choice.
- B. Correct. Up to the probabilities the model is deterministic, and then temperature adds a little noise before choosing. That is intended, so that output is not flat and repetitive, and it means two runs of the same prompt normally differ.
- C. Not quite. The parameters are fixed once training ends; a chat does not teach the model anything that survives into the next one. What differs between the two runs is the path taken through the same probabilities, not the model itself.
- D. Not quite. The decoder stacks give the same probabilities for the same context every time; there is no glitch to find there. The difference enters after the stacks, at the moment a token is chosen with a little noise.
